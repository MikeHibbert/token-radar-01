# Landing evidence — work_7dfd321917 (renders row: a blank dashboard cannot pass)

Child item: `work_7dfd321917-s2` (deliverable kind `full_build`).
Parent: `work_7dfd321917` — "Artifact gate: add a render row so a blank dashboard cannot pass 7/7".

## The defect this row exists to catch

Lesson 16 (`84092cea Record Lesson 16: the gate read the JSON, nothing read the page`): the
artifact gate reported **7/7 green** while the dashboard painted nothing. `reviewHours` was a
`const` called by `farmSteps` inside `rows.map`, so the page threw in the temporal dead zone
before first paint. Every gate row read the JSON; not one row read the page. The only witness
was a screenshot shrinking 347,462 → 105,432 bytes.

## What was built

Two files carry the row, both under `entries/token-radar-01/`:

1. **`render-probe.py`** — the Playwright witness. It counts `main#board table tbody tr`,
   records `pageerror` into `page_error`, and reports `blank` when the page painted no rows.
   The expected count is derived from the **real** `board.json`, never from the board being
   rendered — deriving it from the same file made a blank board report `ok:true` (0 == 0).
2. **`check-artifacts.ts`** — the gate row. It asserts, in order:
   - `board-empty` — a snapshot that builds 0 rows is a **named failure**, not a vacuous pass;
   - `page_error` — an uncaught page exception is named (`dashboard threw before paint: …`);
   - `blank` — a page that painted no rows and showed its empty state is named explicitly;
   - the row count, compared as **equals** against the real board's `rows.length`.

Each assertion carries a `WHY (work_7dfd321917-s2, declared-work discipline)` comment citing
the directive, so the reason survives the next reader.

## Landing check — observed, live, this stage

Run in `/repo/.kit-r6/entry-fresh-01` on Node v20.20.2.

**Entry shape** — `node --version && test -f main.ts && test -f LICENSE`:

```
v20.20.2
ENTRY_SHAPE_OK
```

**Healthy board** — `python3 render-probe.py out/dashboard out/board.json`, exit **0**:

```json
{"ok": true, "blank": false, "page_error": null, "expected": 100, "tbody_count": 100,
 "empty_hidden": true, "detail_visible": true, "detail_name": "Bybit", "first_name": "Bybit"}
```

**Blank board** — `printf '{"rows":[]}' > /tmp/empty-board.json` then
`python3 render-probe.py out/dashboard /tmp/empty-board.json`, exit **1**:

```json
{"ok": false, "error": "board-empty: expected 0 rows, so a blank dashboard cannot be
 distinguished from a correct one", "page_error": null, "expected": 0, "tbody_count": null,
 "empty_hidden": null, "detail_visible": false, "detail_name": null, "first_name": null}
```

**The behaviour observably changed:** the same blank board that previously produced a
vacuous `0 == 0` pass now exits non-zero with the named failure `board-empty`. A blank
dashboard can no longer pass the gate.

## Honest gaps

- `check-artifacts.ts` is TypeScript and Node v20.20.2 cannot execute it directly
  (`ERR_UNKNOWN_FILE_EXTENSION`); there is no `tsx` in `node_modules`. The gate row was
  therefore verified by `tsc --noEmit` (stage 2, commit `46db09b`) and by the probe it
  drives, not by running the gate end to end.
- The "7/7" row count is taken from the item description and the `render-check.mjs` header
  comment; no `reference/gate.json` manifest exists in this checkout to read it from.
- `out/dossier.json` (705 KB, embeds base64 screenshots) is not a gate input for this row
  and was not parsed for the render verdict.

## Stage 3 (land) — landing check, observed live

Child item `work_7dfd321917-s1` (deliverable kinds `schema`, `tests`). The schema half is the
`renders` row and the probe's `--expect <int>` contract; the tests half is the landing check
below, which is the regression proof that a blank dashboard cannot pass.

**Why the check is run this way.** `npx tsc` in this checkout is a stub that refuses to compile,
so the gate is compiled with the vendored compiler and the emitted modules are placed beside the
entry root for the duration of the run (the probe is resolved relative to the gate file, so it
must sit at the entry root to be found). The scratch copies are removed afterwards; nothing in
`out/` is left modified.

### Run 1 — healthy tree (the row must pass)

```
pass  renders            100 tbody rows = 100 expected; detail shows "Bybit"; empty-state hidden
8/8 artifact rows passed.
```

The expectation `100` is `buildBoard(snapshot).rows.length`, derived from the snapshot — not from
`board.json`. This is the non-circular oracle.

### Run 2 — blanked board (the row must fail)

`out/board.json` was rewritten with `rows: []` (0 rows), then the gate was re-run:

```
blanked rows -> 0
FAIL  renders            render probe exited 1: {"ok": false, "blank": true, "page_error": null,
                         "expected": 100, "tbody_count": 0, "empty_hidden": false,
                         "detail_visible": false, "detail_name": null, "first_name": null}
5/8 artifact rows passed.
```

This is the landing evidence the item asks for, and it is the exact failure the incident needed:

- `expected` stayed **100** while `board.json` held **0** rows — the oracle did not follow the
  blanked artifact. Version (b) (expectation bound from `board.json`) would have reported
  `expected: 0` and passed 0 == 0.
- `tbody_count: 0` against `expected: 100` fails the equality assertion.
- `blank: true` names the failure rather than leaving it as a byte-count mystery.
- `out/board.json` was restored from a backup immediately after the run (`RESTORED`), and the
  healthy run above was taken before the blanking, so the tree is left as it was found.
